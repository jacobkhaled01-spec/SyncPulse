01 // THE DIAGNOSTIC

لماذا قمنا ببناء نظام SyncPulse؟

معالجة تحديات الاعتماد على السحابة الخارجية في الشبكات والبيئات المعزولة

⚠️ مخاطر وتحديات التطبيقات السحابية

CLOUD RISKS
  • توقف الاتصال: انقطاع الخدمة فورياً عند انقطاع كابل الإنترنت الخارجي.
  • انعدام الخصوصية: تسريب البيانات والملفات الحساسة لخوادم وسيطة خارجية.
  • هدر النطاق الترددي والبطء: زمن تأخير مرتفع (150ms - 300ms) لمرور البيانات بالإنترنت.

✅ الحل المعماري في نظام SyncPulse

LOCAL SOVEREIGNTY
  • استقلالية محلية تامة (100% On-Premise LAN): عمل متواصل بدون إنترنت.
  • سيادة وأمان بيانات: تشفير كلمات المرور بـ PBKDF2 وتوكنات JWT.
  • سرعة واستجابة لحظية: نقل وسائط فائق بأقل من 10ms داخل الشبكة المحلية.
02 // ARCHITECTURE

معمارية النظام وفق معايير Clean Architecture

فصل فيزيائي تام للمسؤوليات لمنع التكرار وتسهيل التوسع والصيانة

📦 النواة المشتركة (Core)

CLASS LIB
  • ترويسة التأطير: 12-Byte FrameHeader.
  • محرك التشفير: PBKDF2 وتوكنات JWT.
  • عقد البيانات: نماذج DTOs وأنواع الحزم.
  • اكتشاف الشبكة: خدمة UDP Auto-Discovery.

🖥️ الخادم المركزي (Server)

IOCP ENGINE
  • خادم TCP: استماع غير حاجب على المنفذ 8888.
  • مكرر الوسائط: تدفقات UDP Relay على المنفذ 8889.
  • قاعدة البيانات: SQLite 3NF بوضع WAL Mode.
  • المزامنة: طابور الرسائل المعلقة Offline Queue.

💻 تطبيق العميل (Client)

WPF MVVM
  • المقابس غير الحاجبة: خدمة ClientNetworkService.
  • محرك الصوت: معيار 16kHz HD Voice بالمخازن الدائرية.
  • محرك الفيديو: مكتبة AForge DirectShow & PiP.
  • عرض الميديا: عرض الصور والوسائط بنمط تليجرام.
03 // PROTOCOL & FRAMING

بروتوكول التأطير الثنائي (12-Byte FrameHeader)

حل معضلة تجزئة ودمج دفق TCP بترتيب Big-Endian الشبكي الموحد

📐 تركيبة الترويسة الثنائية

12 BYTES BIG-ENDIAN
Magic 0x53 ('S')
Version 0x01
Type Int16 (2B)
Length Int32 (4B)
Seq Int32 (4B)
FrameHeader.cs - BigEndian Serialization
byte[] buf = new byte[12];
buf[0] = 0x53; buf[1] = 0x01;
BinaryPrimitives.WriteInt16BigEndian(buf.AsSpan(2, 2), (short)PacketType);
BinaryPrimitives.WriteInt32BigEndian(buf.AsSpan(4, 4), PayloadLength);
BinaryPrimitives.WriteInt32BigEndian(buf.AsSpan(8, 4), SequenceNumber);
return buf;

⚙️ آلة حالة فك التأطير (Parser State Machine)

PARSER FLOW
  • 1. التجميع في المخزن: قراءة دفق TCP المستمر دون افتراض وصول الحزمة دفعة واحدة.
  • 2. فحص الـ Magic Byte: التحقق من بايت 0x53 فور اكتمال 12 بايت واستخراج طول الحمولة.
  • 3. تسليم الحزمة الكاملة: اقتطاع الحمولة بدقة وتدوير البايتات للحزمة التالية.
  • ★ أهمية Big-Endian: توحيد قراءة الأرقام بين معالجات x86 ومعالجات ARM.

05 // SECURITY & CRYPTO

الأمن السيبراني والمصادقة المشفرة (PBKDF2 & JWT)

تطبيق أعلى المعايير القياسية (NIST SP 800-63B & RFC 7519) لحماية المستخدمين

🔐 تجزئة كلمات المرور

PBKDF2
  • 128-bit Salt: ملح عشوائي فريد يبطل هجمات جداول قوس قزح.
  • 100,000 تكرار: إبطاء هجمات التخمين بالقوة الغاشمة.
  • FixedTimeEquals: حماية تامة من هجمات التوقيت (Timing Attacks).

🎫 إدارة الجلسات

JWT RFC 7519
  • توقيع HMAC-SHA256: منع تزوير بيانات التوكن.
  • تحقق رياضي لحظي: التحقق دون استعلام قاعدة البيانات في كل حزمة.
  • انتهاء تلقائي: إدارة دورة حياة الجلسات بأمان.

🛡️ التحصين وسجلات التدقيق

ISO 27001
  • Parameterized Queries: حماية قاعدة البيانات من حقن SQL.
  • سقف 10MB للحزمة: حماية الخادم من هجمات حجب الخدمة (DoS).
  • سجلات ISO 27001: توثيق عمليات الدخول في جدول التدقيق.
06 // CONCURRENCY & DB

التزامن الفائق بـ IOCP وعزل الأعطال و SQLite WAL Mode

خدمة مئات المتصلين دون اختناق الخيوط مع مناعة تامة ضد الانهيار

⚡ نموذج التزامن وعزل الجلسات

IOCP & BULKHEAD
  • منافذ إكمال الإدخال/الإخراج (IOCP): استخدام async/await دون حجز خيوط في وضع الانتظار.
  • تجنب اختناق الخيوط: تفادي عيوب حجز خيط لكل عميل (Thread-per-Client).
  • نمط الحواجز (Bulkhead): عزل كل عميل في كتلة معالجة مستقلة لمنع انهيار الخادم.

🗄️ قاعدة بيانات SQLite 3NF ووضع WAL

WAL MODE
  • وضع WAL Mode: قراءات متزامنة لا نهائية أثناء الكتابة دون أي أقفال حظر.
  • تصميم الشكل المعياري 3NF: 7 جداول مترابطة بمفاتيح أجنبية تمنع تكرار البيانات.
  • المعاملات الذرية (ACID): ضمان سلامة وتناسق الرسائل والمكالمات.
07 // REAL-TIME MEDIA

محرك الصوت 16kHz HD ومحرك الفيديو المباشر AForge

القضاء التام على خطأ الذاكرة 0xc0000005 والتحكم الفيزيائي بإطفاء ضوء الكاميرا LED

🎙️ محرك الصوت والمخازن الدائرية الثابتة

PRE-PINNED RING
  • تثبيت 8 مخازن مسبقاً: حجز وتثبيت 8 مخازن بـ GCHandleType.Pinned مرة واحدة فقط عند بدء المكالمة.
  • Zero-Allocation: نسخ البيانات عبر Buffer.BlockCopy دورياً داخل المخزن التالي: (_outIndex + 1) % 8.
  • استقرار 100%: صفر استدعاءات للـ GC وصفر تجميد للواجهة.

📹 محرك الفيديو وإطفاء ضوء الكاميرا الحقيقي

DIRECTSHOW LED
  • مكتبة AForge DirectShow: تعامل مباشر مع مقبض الكاميرا في نظام التشغيل.
  • إغلاق فيزيائي: إرسال إشارة SignalToStop() فينطفئ ضوء الـ LED الحقيقي لحماية الخصوصية.
  • البث الهجين (UDP+TCP): قناتان متوازيتان مع إلغاء تكرار الإطارات لحظياً.
