01. الدوافع والأهداف الهندسية

لماذا قمنا ببناء نظام SyncPulse؟

معالجة تحديات الاعتماد على الإنترنت السحابي في البيئات المؤسسية والشبكات المعزولة

⚠️

تحديات التطبيقات السحابية التقليدية

  • الاعتماد الحتمي على الإنترنت الخارجي: توقف الاتصال بالكامل داخل المنشأة عند انقطاع كابل الإنترنت أو ضعف المزود.
  • انعدام السيادة الرقمية والخصوصية: مرور الرسائل والملفات الحساسة عبر خوادم أجنبية خارجية تعرضها للتنصت والتحليل.
  • هدر النطاق الترددي والبطء: رفع وتحميل الوسائط عبر الإنترنت بينما الأجهزة متواجدة على نفس شبكة الواي فاي المحلية.
✅

الحل المبتكر في SyncPulse

  • استقلالية محلية تامة (100% On-Premise): خادم محلي خفيف يعمل بكفاءة قصوى داخل الشبكة المحلية (LAN / WLAN) بدون إنترنت.
  • سيادة وأمان بيانات عالي: لا تخرج أي بايت خارج أسوار المؤسسة، مع تشفير كلمات المرور بـ PBKDF2 وجلسات JWT.
  • استجابة لحظية وسرعة فائقة: استغلال سرعة الشبكة المحلية الكاملة (Gigabit / Wi-Fi 6) لبث الصوت والفيديو بأقل من 10ms.

03. هندسة المقابس وبروتوكول التأطير

حل معضلة دفق TCP ببروتوكول التأطير الثنائي (12-Byte Header)

التغلب الحتمي على مشاكل دمج الحزم (Packet Merging) وتجزئتها (Fragmentation)

📐 تركيبة الترويسة الثنائية (12-Byte FrameHeader)

Magic 0x53 ('S') 1 Byte
Version 0x01 1 Byte
PacketType Short (Int16) 2 Bytes
PayloadLength Length (Int32) 4 Bytes
SequenceNumber Seq # (Int32) 4 Bytes
FrameHeader.cs (ترتيب بايتات الشبكة Big-Endian)
public byte[] ToBytes() {
    byte[] buf = new byte[12];
    buf[0] = 0x53; buf[1] = 0x01;
    BinaryPrimitives.WriteInt16BigEndian(buf.AsSpan(2, 2), (short)PacketType);
    BinaryPrimitives.WriteInt32BigEndian(buf.AsSpan(4, 4), PayloadLength);
    BinaryPrimitives.WriteInt32BigEndian(buf.AsSpan(8, 4), SequenceNumber);
    return buf;
}

⚙️ آلة حالة فك التأطير (FrameStreamParser State Machine)

1
تجميع البايتات في المخزن المؤقت: استقبال بايتات دفق TCP دون الاعتماد على حدود القراءة (`Read`).
2
التحقق من الـ Magic Byte وقراءة الترويسة: فور اكتمال 12 بايت يتم فحص `0x53` واستخراج طول الحمولة `PayloadLength`.
3
اقتطاع الحزمة بدقة متناهية: بمجرد وصول بايتات الحمولة بالكامل، يتم تسليم الحزمة ومعالجة ما بعدها فورياً دون أي تداخل.
💡 ترتيب Big-Endian: يضمن التوافق 100% بين مختلف المعالجات (x86 vs ARM) ويمنع انهيار الترويسة عبر الشبكة.
04. الاكتشاف التلقائي لشبكات الواي فاي

ميزة Zero-Configuration Auto-Discovery (UDP Port 8887)

اتصال العملاء بالخادم فورياً وبشكل ذاتي على نفس الشبكة دون كتابة عنوان IP يدوياً

📡

1. إعلان الخادم الدوري (Server Announce)

يبث الخادم حزمة برودكاست خفيفة كل 3 ثوانٍ على عنوان `255.255.255.255` ومنفذ `8887` تحوي رمز التحقق والمنفذ.

SYNCPULSE_SERVER_ANNOUNCE:8888
➔
🔍

2. التقاط العميل للإعلان (Client Listen)

عند فتح العميل، يستمع على المنفذ `8887`، ويلتقط حزمة الخادم فورياً ويستخرج عنوان IP الفعلي للخادم من ترويسة الحزمة.

serverIP = result.RemoteEndPoint.Address
➔
⚡

3. بدء الاتصال الفوري (TCP Handshake)

يبدأ العميل مصافحة TCP فورياً على المنفذ `8888` ويسجل دخوله بسلاسة تامة وتجربة مستخدم لا تضاهى.

await client.ConnectAsync(serverIP, 8888)
🛡️

فائدة معمارية الاكتشاف التلقائي في مقرر خادم وعميل:

إثبات تطبيق بروتوكول UDP Broadcast في إدارة الشبكات المحلية، وحل مشكلة تغير عناوين الـ DHCP الديناميكية في شبكات الواي فاي والمقاهي والجامعات بدون الحاجة لإعداد خوادم DNS مخصصة.

05. الأمن السيبراني والمصادقة

المصادقة المشفرة بـ PBKDF2/SHA-256 وتوكنات JWT

تطبيق أعلى المعايير المصرفية (NIST SP 800-63B & RFC 7519) لحماية بيانات المستخدمين

تشفير كلمات المرور

PBKDF2/SHA-256

  • 128-bit Salt: ملح عشوائي مشفر ومستقل لكل مستخدم يبطل هجمات جداول قوس قزح (Rainbow Tables).
  • 100,000 دورة تكرار: إبطاء هجمات التخمين بالقوة الغاشمة (GPU Brute-Force).
  • FixedTimeEquals: مقارنة زمنية ثابتة تحمي النظام من هجمات التوقيت (Timing Attacks).
إدارة الجلسات

JWT Tokens (RFC 7519)

  • HMAC-SHA256: توقيع رقمي بمفتاح سري مشفر على الخادم يمنع تزوير التوكن (Token Tampering).
  • Stateless Verification: التحقق من صحة التوكن رياضياً فور وصول أي حزمة دون الحاجة للاستعلام في قاعدة البيانات.
  • دورة حياة محددة: إدارة توقيت انتهاء الصلاحية والتجديد التلقائي.
التحصين وسجلات التدقيق

Injection & ISO 27001

  • Parameterized Queries: حماية قاعدة البيانات 100% من هجمات حقن SQL (SQL Injection).
  • سقف الحزمة 10MB: منع هجمات حجب الخدمة (DoS) واستنزاف الذاكرة.
  • سجلات تدقيق SERVER_AUDIT_LOGS: توثيق عمليات الدخول وعناوين IP وفق معايير التدقيق الأمني.
06. معمارية الخادم وقواعد البيانات

التزامن الفائق بـ IOCP ووضع SQLite WAL Mode وعزل الأعطال

خدمة مئات الاتصالات المتزامنة دون اختناق الخيوط مع مناعة تامة ضد الانهيار

⚡ نموذج التزامن وعزل الجلسات (Bulkhead Pattern)

  • I/O Completion Ports (IOCP): استخدام `AcceptTcpClientAsync` و `ReadAsync` غير الحاجبة؛ الخادم لا يحجز خيطاً أثناء انتظار البيانات بل يستيقظ الخيط فقط عند وصول بايتات حقيقية من بطاقة الشبكة.
  • حماية مصفوفة الخيوط (No Thread Starvation): تجنب عيوب نموذج (Thread-per-Client) الذي يستهلك 1MB لكل خيط ويسبب عبء تبديل السياق (Context Switching).
  • نمط الحواجز المقسمة (Bulkhead): كل جلسة عميل معزولة في كتلة `try-catch-finally`؛ انقطاع أو خطأ أي عميل يحرر مقبسه بأمان دون التأثير على بقية المتصلين.

🗄️ قاعدة بيانات SQLite 3NF ووضع WAL Mode

PRAGMA journal_mode = WAL; PRAGMA foreign_keys = ON;
  • قراءات وكتابات متزامنة بدون أقفال: في وضع WAL (Write-Ahead Logging)، عمليات القراءة لا تحجب الكتابة، والكتابة لا تحجب القراءة (Readers never block Writers).
  • تصميم الشكل المعياري الثالث (3NF): 7 جداول مرتبطة بعلاقات متكاملة وفهارس ذكية تمنع تكرار البيانات وتسرع الاستعلام.
  • المعاملات الذرية (ACID Transactions): ضمان حفظ الرسائل وحالات التسليم وسجلات المكالمات بتناسق كامل.
07. دورة حياة الرسائل والمزامنة التلغرامية

طابور الرسائل المعلقة (Offline Queue) ومؤشرات التسليم (✓✓)

مزامنة فائقة تحاكي بروتوكول تليجرام لضمان عدم ضياع أي رسالة حتى عند انقطاع المستلم

✓
Sent (0)

تُرسل الرسالة من العميل الأول وتُحفظ فورياً في قاعدة بيانات الخادم بحالة أُرسلت (صح واحدة رمادية).

➔
⏳
Offline Queue

إذا كان المستلم غير متصل، يحتفظ الخادم بالرسالة في طابور الانتظار ويدفعها تلقائياً فور اتصاله.

➔
✓✓
Delivered (1)

فور وصول الرسالة لجهاز المستلم، يُرسل إشعار تسليم للخادم وللمرسل لتتحول إلى (علامتي صح رماديتين).

➔
✓✓
Read (2)

عند فتح المستلم لشاشة المحادثة، يُرسل إشعار قراءة `MessageReadAck` لتتحول إلى (علامتي صح زرقاوين).

كشف المقابس المعلقة (Half-Open Sockets):

فحص القراءة الصفرية `ReadAsync() == 0` وبروتوكول نبضات القلب `Heartbeat` كل 30 ثانية لتنظيف المقابس التالفة فورياً.

أمان الخيوط (Thread Safety):

إدارة الجلسات عبر `ConcurrentDictionary` وأقفال المزامنة لمنع أي تضارب بين خيوط الإرسال والاستقبال.

08. معالجة الصوت والذاكرة منخفضة المستوى

محرك الصوت 16kHz HD Voice ونظام المخازن الدائرية الثابتة

القضاء التام والنهائي على خطأ الوصول غير المصرح به للذاكرة (0xc0000005 Status Access Violation)

السبب الجذري لخطأ الذاكرة

معضلة خطأ الذاكرة 0xc0000005

في معالجة الصوت المباشر عبر واجهات Windows Multimedia (WinMM P/Invoke):

  • الحجز والتحرير الديناميكي المتكرر: حجز مصفوفة بايتات وتثبيتها (`GCHandle.Alloc`) وتحريرها لكل مقطع صوتي (40ms) كان يربك الـ Garbage Collector.
  • تضارب مع قنوات DMA في بطاقة الصوت: تحرير مؤشرات `WAVEHDR` بينما كارت الصوت لا يزال يقرأ من الذاكرة كان يرمي استثناء الانهيار الحتمي `0xc0000005`.
الحل الهندسي المبتكر

Pre-Pinned Circular Ring Buffers

  • تثبيت 8 مخازن بحجم ثابت مسبقاً: حجز وتثبيت 8 مخازن في الذاكرة عبر `GCHandleType.Pinned` مرة واحدة فقط عند بدء المكالمة.
  • Zero-Allocation أثناء المكالمة: نسخ البيانات الصوتية فقط عبر `Buffer.BlockCopy` داخل المخزن التالي دورياً: idx = (_outBufferIndex + 1) % 8;
  • انعدام عبء الـ GC: صفر حجز ديناميكي، صفر تجميد، وأداء فائق بدون أي انهيار.
معدل العينات (Sampling Rate) 16,000 Hz (HD Voice)
عمق العينة (Bit Depth) 16-bit PCM Mono
حجم الإطار الصوتي (Frame Size) 1,280 Bytes / 40 ms
استهلاك الذاكرة والمعالج < 1% CPU / Zero GC
09. الفيديو والبث الهجين والخصوصية الفيزيائية

محرك الفيديو المباشر AForge والبث الهجين (UDP+TCP)

تحكم فيزيائي بضوء الكاميرا (LED) في طبقة النواة، المعاينة الذاتية PiP، وإلغاء تكرار الإطارات

التحكم الفيزيائي

إطفاء ضوء الكاميرا (LED)

  • مكتبة AForge DirectShow: التعامل المباشر مع مقبض الكاميرا في نظام التشغيل (Kernel Video Stream Handle).
  • إغلاق الدائرة الكهربائية: عند كتم الفيديو يتم إرسال إشارة إيقاف حقيقية `_videoSource.SignalToStop()` فينطفئ ضوء الـ LED الحقيقي على اللابتوب لحماية الخصوصية.
البث الهجين

Hybrid UDP + TCP

  • تخطي جدران الحماية: إرسال حزم الصوت والفيديو عبر UDP (قناة سريعة) و TCP (قناة مضمونة) بالتوازي.
  • إلغاء التكرار اللحظي (Deduplication): مفتاح ثنائي 64-بت: key = ((long)Type << 32) | Seq لتشغيل الإطار الأسرع فوراً ورفض النسخة المكررة.
عرض الميديا بنمط تليجرام

Inline Telegram Media

  • عرض الصور داخل الفقاعة: تحويل بايتات الصور لـ `BitmapSource` مفرزة وعرضها مباشرة بحواف منحنية.
  • بطاقات الصوت والمستندات: مشغل صوت مدمج مع زر `▶` وبطاقات ذكية للمستندات (PDF, ZIP) مع أزرار الفتح والحفظ.
