CLOUD RISKS

SOCKETS & PROTOCOL // 04

مخطط بروتوكول التأطير الثنائي (12-Byte FrameHeader)

التغلب على مشاكل دمج وتجزئة الحزم في دفق بايتات TCP

04 / 13

📐 تفصيل حقول الترويسة الثنائية

12 BYTES BIG-ENDIAN
Magic 0x53 ('S')
Version 0x01
Type Int16 (2B)
Length Int32 (4B)
Seq Int32 (4B)
FrameHeader.cs - BigEndian Serialization
byte[] buf = new byte[12];
buf[0] = 0x53; buf[1] = 0x01;
BinaryPrimitives.WriteInt16BigEndian(buf.AsSpan(2, 2), (short)PacketType);
BinaryPrimitives.WriteInt32BigEndian(buf.AsSpan(4, 4), PayloadLength);
BinaryPrimitives.WriteInt32BigEndian(buf.AsSpan(8, 4), SequenceNumber);
return buf;

⚙️ آلة حالة فك التأطير (State Machine)

PARSER FLOW
  • 1. التجميع في المخزن: قراءة دفق TCP المستمر دون افتراض وصول الحزمة دفعة واحدة.
  • 2. فحص الـ Magic Byte: التحقق من بايت 0x53 فور اكتمال 12 بايت واستخراج طول الحمولة.
  • 3. تسليم الحزمة الكاملة: اقتطاع الحمولة بدقة وتدوير البايتات للحزمة التالية.
  • ★ أهمية Big-Endian: توحيد قراءة الأرقام بين معالجات x86 ومعالجات ARM.

SECURITY ENGINE // 06

مخطط الأمن السيبراني والمصادقة المشفرة (PBKDF2 & JWT)

تطبيق أعلى المعايير القياسية (NIST SP 800-63B & RFC 7519) لحماية المستخدمين

06 / 13

🔐 تجزئة كلمات المرور

PBKDF2/SHA-256
  • 128-bit Salt: ملح عشوائي فريد يبطل هجمات جداول قوس قزح.
  • 100,000 تكرار: إبطاء هجمات التخمين بالقوة الغاشمة.
  • FixedTimeEquals: حماية تامة من هجمات التوقيت (Timing Attacks).

🎫 إدارة الجلسات

JWT RFC 7519
  • توقيع HMAC-SHA256: منع تزوير بيانات التوكن.
  • تحقق رياضي لحظي: التحقق دون استعلام قاعدة البيانات في كل حزمة.
  • انتهاء تلقائي: إدارة دورة حياة الجلسات بأمان.

🛡️ التحصين وسجلات التدقيق

ISO 27001
  • Parameterized Queries: حماية قاعدة البيانات من حقن SQL.
  • سقف 10MB للحزمة: حماية الخادم من هجمات حجب الخدمة (DoS).
  • سجلات ISO 27001: توثيق عمليات الدخول في جدول التدقيق.

CONCURRENCY // 07

مخطط التزامن الفائق بـ IOCP وعزل الأعطال ووضع SQLite WAL Mode

خدمة مئات المتصلين دون اختناق الخيوط مع مناعة تامة ضد الانهيار

07 / 13

⚡ نموذج التزامن وعزل الجلسات

IOCP & BULKHEAD
  • منافذ إكمال الإدخال/الإخراج (IOCP): استخدام async/await دون حجز خيوط في وضع الانتظار.
  • تجنب اختناق الخيوط: تفادي عيوب حجز خيط لكل عميل (Thread-per-Client).
  • نمط الحواجز (Bulkhead): عزل كل عميل في كتلة معالجة مستقلة لمنع انهيار الخادم.

🗄️ قاعدة بيانات SQLite 3NF ووضع WAL

WAL MODE
  • وضع WAL Mode: قراءات متزامنة لا نهائية أثناء الكتابة دون أي أقفال حظر.
  • تصميم الشكل المعياري 3NF: 7 جداول مترابطة بمفاتيح أجنبية تمنع تكرار البيانات.
  • المعاملات الذرية (ACID): ضمان سلامة وتناسق الرسائل والمكالمات.

مخطط دورة حياة الرسائل وطابور الانتظار (Offline Queue Pipeline)

مزامنة فائقة لضمان عدم ضياع أي رسالة حتى عند انقطاع المستلم

08 / 13
1 Sent (✓)

تُرسل الرسالة وتُحفظ فوراً في قاعدة بيانات الخادم (صح رمادية واحدة).

➔
2 Offline Queue

إذا كان المستلم غير متصل، يحتفظ الخادم بالرسالة ويدفعها له فور اتصاله.

➔
3 Delivered (✓✓)

فور استلام العميل، يُرسل إشعار تسليم فتتحول لـ (علامتي صح رماديتين).

➔
4 Read (✓✓)

عند فتح المستلم للمحادثة، يُرسل إشعار قراءة فتتحول لـ (علامتي صح زرقاوين).

HALF-OPEN

🔒 أمان الخيوط المتزامنة

THREAD SAFETY

إدارة الجلسات عبر ConcurrentDictionary وأقفال المزامنة لمنع أي تضارب بين الخيوط المتزامنة.

AUDIO & MEMORY // 09

مخطط معالجة الصوت منخفض المستوى والمخازن الدائرية الثابتة

القضاء التام والنهائي على خطأ الوصول غير المصرح به للذاكرة (0xc0000005 Status Access Violation)

09 / 13

⚠️ معضلة خطأ الذاكرة 0xc0000005

ACCESS VIOLATION
  • الحجز المتكرر: حجز وتثبيت مصفوفة بايتات لكل إطار صوتي (40ms) كان يربك مجمع القمامة (GC).
  • تضارب مع بطاقة الصوت: تحرير مؤشرات WAVEHDR أثناء قراءة بطاقة الصوت كان يسبب انهيار البرنامج.

✅ الحل: المخازن الدائرية الثابتة

PRE-PINNED BUFFERS
  • تثبيت 8 مخازن مسبقاً: حجز وتثبيت 8 مخازن بـ GCHandleType.Pinned مرة واحدة فقط عند بدء المكالمة.
  • Zero-Allocation: نسخ البيانات عبر Buffer.BlockCopy دورياً داخل المخزن التالي: (_outIndex + 1) % 8.
  • استقرار 100%: صفر استدعاءات للـ GC وصفر تجميد للواجهة.
